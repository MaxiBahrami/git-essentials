Branching & collaboration

Build features independently, review teammates’ code, and merge with confidence.

Why branches exist

A branch is a movable pointer to a series of commits. It gives you a separate place to develop a feature or fix while the main branch remains stable. Multiple people can work in parallel without constantly editing the same version of the project.

Create and switch branches

Start from the latest version of main and choose a descriptive branch name.

Terminal
git switch main
git pull origin main
git switch -c feature/branching-guide
git branch
git branch --show-current

For older Git versions, git checkout -b feature/branching-guide performs the creation and switch in one command.

Pull requests and code reviews

Push your branch and open a pull request on GitHub. A PR proposes a set of changes; teammates can discuss them before they enter main.

Terminal
git add branching.html
git commit -m "Document Git branching"
git push -u origin feature/branching-guide
  1. Open the repository on GitHub and select Compare & pull request.
  2. Describe what changed and which pages should be checked.
  3. Ask another team member to open Files changed, review the code and select Review changes.
  4. The reviewer can comment, approve, or request changes.
  5. Once ready, select Merge pull request if you have permission and branch rules allow it.

Merge and close branches

GitHub’s Merge pull request is the easiest approach for a team. You can also merge locally when appropriate:

Terminal
git switch main
git pull origin main
git merge feature/branching-guide
git push origin main
git branch -d feature/branching-guide
git push origin --delete feature/branching-guide

-d deletes a local branch only when Git considers it safely merged. git push origin --delete removes the remote branch. Never delete work that has not been merged or otherwise saved.

Resolve a merge conflict

A conflict can happen when two branches change overlapping lines. Git stops and asks you to resolve the competing edits.

Terminal
git switch main
git pull origin main
git switch feature/branching-guide
git merge main
git status

Open the conflicting file. Git may show markers like these:

Conflict example
<<<<<<< HEAD
Our branch version
=======
Main branch version
>>>>>>> main
  1. Discuss which content is correct or combine both versions.
  2. Remove the conflict markers and save the final file.
  3. Test the page or app before committing.
  4. Run the commands below to finish the merge.
Terminal
git add branching.html
git commit -m "Resolve branching page conflict"
git push

If you are not ready to resolve a merge in progress, use git merge --abort to attempt to return to the pre-merge state.

Team branching conventions

  • Use clear names: feature/navigation, fix/mobile-layout, docs/readme.
  • Keep each pull request focused and small enough to review.
  • Pull updates before starting and before merging long-lived branches.
  • Leave constructive review comments and test on desktop and mobile.
  • Make sure every teammate has their own branch, commit, pull request, merge, and review history.
