Why remote repositories matter

Your local repository lives on your own computer. A remote repository, such as one hosted on GitHub, gives the team a shared place to exchange code, review changes, and coordinate work. It also provides an additional copy of pushed commits, but it is not a replacement for a complete backup strategy.

Git works offline; GitHub is optional for version control, but extremely useful for team collaboration.

Create a repository on GitHub

  1. Sign in to github.com and choose New repository.
  2. Enter a repository name, such as git-guide, and add a description.
  3. Choose Public if you want to publish the site using GitHub Pages on a free account.
  4. If you already have local files to push, leave Add a README unchecked to avoid an unnecessary initial-history conflict.
  5. Select Create repository and copy the HTTPS URL.

Create the project locally

Make a folder, start Git, add a first file, and record your initial snapshot. Install Git first and configure your identity once.

Terminal
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
mkdir git-guide
cd git-guide
git init
git branch -M main
# Create index.html in your editor
git add index.html
git commit -m "Add initial homepage"

git status reports which files have changed, and git log --oneline shows your history.

Connect local and remote repositories

Use your real GitHub username and repository name in place of the examples below.

Terminal
git remote add origin https://github.com/USERNAME/git-guide.git
git remote -v
git push -u origin main

origin is a conventional name for your remote. -u sets an upstream branch so that later you can usually use git push without specifying the destination.

Alternative: clone an existing remote project

Terminal
git clone https://github.com/USERNAME/git-guide.git
cd git-guide

git clone downloads a repository and normally sets up origin automatically.

Invite others to contribute

  1. Go to your GitHub repository → Settings → Collaborators (or the relevant access-management area).
  2. Invite your teammates by their GitHub usernames and have them accept.
  3. Each teammate clones the repository and creates a separate feature branch.
  4. After changing files, they push their branch and open a pull request (PR).
  5. Another teammate reviews the PR before it is merged into main.
Team rule: Prefer feature branches and pull requests instead of committing everyone’s work directly to main.
