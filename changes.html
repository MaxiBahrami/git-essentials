The everyday workflow

The normal loop is pull → edit → check → stage → commit → push → open PR. Each commit should describe one meaningful change. Work in a feature branch when collaborating.

Get the latest changes

Before starting a new feature, return to the main branch and bring it up to date.

Terminal
git switch main
git pull origin main
git switch -c feature/contact-section

git fetch origin only downloads remote updates; git pull downloads and integrates them. Pull may merge or rebase depending on your configuration.

Stage and commit your work

After editing files, inspect your changes. Stage specific files when possible, then commit with a clear message.

Terminal
git status
git diff
git add index.html assets/style.css
git diff --staged
git commit -m "Add responsive navigation"
git log --oneline -5

git add . stages all changes in the current directory and below; review git status first so you do not include unintended files.

Push a feature branch

Share your commits with GitHub so teammates can review them.

Terminal
git push -u origin feature/contact-section

On GitHub, select Compare & pull request. Write a short summary, select main as the base, and request a review. After approval, merge the PR using the GitHub interface.

Useful commands and common mistakes

Command When to use it
git status Check the branch and pending changes.
git diff Inspect unstaged edits.
git restore file.html Discard unstaged changes to a tracked file; use carefully.
git restore --staged file.html Unstage a file without discarding its edits.
git log --oneline See concise commit history.
git stash Temporarily store uncommitted work.
git stash pop Reapply and usually remove the latest stash.
Important: Never commit passwords, API keys, or private files. Add local secrets to .gitignore before staging them. If you already committed a secret, rotating it is necessary; merely deleting the file later does not erase it from history.
